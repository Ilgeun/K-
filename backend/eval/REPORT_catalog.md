# 제조사 카탈로그(스캔 이미지) 읽기 시험 (소규모, 2쪽)

- 작성일: 2026-09-21 · 대상: PK Valve & Engineering 버터플라이 밸브 카탈로그 18쪽 중 **3쪽(규격 목록)·9쪽(치수표)**. 쪽마다 이미지 1장인 스캔 PDF(글자 레이어 없음).
- 방식: `claude -p --tools Read --allowedTools Read` 로 이미지 파일을 읽게 하고 `--json-schema` 로 구조화 출력. **앱 코드에는 아직 연결하지 않았다**(시험용 호출).
- 정답: **추출 결과를 보기 전에** 이미지를 보고 사람이 옮겨 적었다(표 527셀, 목록 사실 26건). 작성자는 Claude 이고 사람 검수 전이다. 정답표·원본 결과는 저작권 자료라 저장소에 넣지 않았다(`backend/data/eval/labels_catalog_*`, `backend/eval/cache_catalog/`는 gitignore).
- 문서 내용이 Anthropic 으로 전송됐다. 이 시험의 CLI 호출은 총 5회(표 읽기 3, 목록 읽기 1, 누락 확인 1)이다.

## 결과

| 시험 | 대상 | 결과 |
|---|---|---|
| 표 읽기 | 9쪽, Class 150·300·600 치수표 | 1회차 **526/527 셀(99.8%)**, 2·3회차 **527/527**. 행 누락 0 |
| 목록 읽기 | 3쪽, STANDARD/OPTION 두 열의 규격 목록 | 사실 26건 중 **24건 일치**, 오답 0, **누락 2**(상단 문장 "ASME B16.34로 설계", "Fire safe design"), 지어낸 항목 0 |
| 표 구조 검사 | 위 표 3회분 | **실제 오답을 못 잡음**(오답 25.4도 오름차순 유지). 대신 원본 표의 이상값 1건 발견(Class 300 20"→24" L1 520→515, 3회 모두 동일하게 읽힘 → 원본 값으로 보임) |
| 3회 읽기 비교 | 9쪽 | 서로 다른 셀 **1개 = 실제 오답 셀**, 오탐 0. 다수결로 정답 복원 |
| 2회 읽기 비교 | 9쪽(1·2회차) | 같은 셀을 경고하나 과반이 없어 **세 번째 읽기가 필요**하다고 표시 |
| 누락 확인 패스 | 3쪽 | 누락 2건을 모두 찾음. 무해한 제목 1개를 추가로 제시(spec=false) |

## 오류의 성격

- **표: 조용한 오답.** 이웃 행의 값을 가져옴(Class 300 6"의 `h1` 22.2 → 25.4). 구조 규칙(단조성·크기 짝·열 간 종속)으로는 걸러지지 않고, **같은 이미지를 독립적으로 여러 번 읽어 비교**해야 잡혔다.
- **목록: 문장 누락.** 페이지 상단의 한 줄 문장(설계 규격, 내화 설계)을 건너뜀. 값이 틀리는 것이 아니라 **없어서** 판정에서 빠질 수 있다. 원문 대조가 아니라 "표에 없는 문장이 있는가"를 묻는 2차 패스로 잡았다.

## 검증 장치(앱 코드: `app/catalog_checks.py`, 테스트 14개)

| 장치 | 잡는 것 | 못 잡는 것 |
|---|---|---|
| `check_table` 구조 검사 | 크기 짝(3"=80mm 등)·순서·중복·열 단조성(원본 이상값은 severity=review) | **그럴듯하게 틀린 값** |
| `check_dependency` | 같은 장착 TYPE인데 치수가 다른 경우 | 위와 같음 |
| `compare_reads` | 읽기끼리 어긋난 셀, 과반 값 제안, 과반 없으면 추가 읽기 필요 | **모든 읽기가 같은 오답인 체계적 오류** |
| 누락 확인 패스(LLM, 앱 미연결) | 추출 목록에 없는 문장 | 페이지 밖 내용, 잘못 읽은 값 |

## 한계 (반드시 함께 말할 것)

1. **표본이 매우 작다.** 2쪽, 오답 1건. 검증 장치가 "오답 1건을 잡았다"는 것이 일반적인 검출률을 뜻하지 않는다.
2. **누락 확인 패스의 지시문은 '3쪽에서 상단 문장이 빠진다'는 것을 안 뒤에 만들었고 같은 쪽에서 시험했다**(지시문 자체는 일반적인 표현이지만 낙관적 수치).
3. 읽기 횟수만큼 시간·사용량이 늘어난다(9쪽 1회 약 50초, 3쪽 약 20초, 누락 확인 약 11초). 호출 비용은 CLI가 보고한 환산값(1회 약 $0.08)만 확인했고 구독 사용량으로 어떻게 잡히는지는 모른다.
4. **서버 배포에서는 Claude CLI를 쓸 수 없다.** 같은 방식을 API 키의 이미지 입력으로 옮겨야 하며 이는 시험하지 못했다.
5. 정답은 Claude 가 이미지를 읽어 옮겼다(틀린 1건은 이미지를 확대해 직접 확인). 같은 계열 모델의 공통 착각이 있을 수 있다.
6. 이 카탈로그는 금속 시트 트리플 오프셋 산업용 밸브다. 선박용 고무 시트 밸브 카탈로그에서도 같은 결과가 나온다는 보장은 없다.

## 시험에 쓴 지시문 요지

- 표: "스캔 카탈로그 이미지의 표를 한 셀도 빠짐없이 그대로 옮겨라. '-'나 빈칸은 null. 값을 추측하거나 계산하지 마라."
- 목록: "STANDARD/OPTION 열을 구분해 기록하고, (규격, Class 묶음, 크기 범위)마다 사실 1건. 페이지에 없는 정보를 더하지 마라. 압력·온도 등급을 추정하지 마라."
- 누락 확인: "이미 추출된 사실 목록과 이미지를 보고, 목록에 없는 문장·항목을 원문 그대로 나열하라. 이미 있는 것은 반복하지 마라."

## 18쪽 전체 1회 실행 (`--workers 3`, CLI)

- **254초**(약 4분 15초), 오류 쪽 0. 분류: 표지 1, 서술 1, 목록 5, 도면 6, 치수표 3(9·11·13쪽, 각 Class 150/300/600 표 3개), 재질표·치수표 혼합 5(6·14~17쪽), 연락처 1.
- 발견: **6쪽은 부품별 재질표**(표준 재질 3벌: 본체 A216-WCB / A217-WC9 / A351-CF8M 등)이고, 14~17쪽은 다른 형식(더블 플랜지 등)의 재질·치수·무게 표다. 이 카탈로그의 본체 재질은 해수 냉각용 요구 재질(NAB, 고무 라이닝 등)과 겹치지 않는 것으로 **읽힌다**(해석은 사람이 확인).
- **셀 경고 40개**: 9쪽 4, 11쪽 30, 13쪽 6. 정답표가 없는 쪽(6, 11, 13~17)은 채점하지 못했다.

## 이번에 발견한 결함과 조치

| 발견 | 조치 |
|---|---|
| **Claude CLI가 결과 JSON 뒤에 로그 한 줄을 stdout으로 섞어 내보내는 경우가 간헐적으로 있다**(`Client.listTools() called but server does not advertise tools capability`). 통째로 `json.loads` 하면 실패 → 기존 텍스트 추출 경로도 같은 방식이라 **잠재 결함**이었다(실패하면 규칙 기반으로 조용히 대체됨) | `extract_cli.parse_output`(첫 JSON 객체만 읽음)으로 두 경로 모두 수정 + 테스트 |
| 11쪽 Class 600 표를 3회 읽었는데 **2회가 같은 실수(C열을 통째로 빠뜨림)** → "가장 많이 나온 형태"를 기준으로 삼아 **맞았을 나머지 1회를 제외**하고 열이 밀린 셀 28개가 경고로 남음(조용히 틀린 값이 통과하지는 않았지만 표는 망가짐) | 제외된 읽기를 쪽 경고로 노출, Class만 다른 같은 종류의 표끼리 열 수가 다르면 경고. 재실행 2회에서 1회는 경고와 함께 17열 채택, 1회는 3회 모두 17열로 일치 |
| 표에 스캔되지 않은 목록 잡음 | 분류의 `has_text` 정의를 '표에 속하지 않는 서술·목록'으로 좁힘, 표지·연락처는 건너뜀 |

## 한계 (반드시 함께 말할 것)

1. **채점한 것은 9쪽 표와 3쪽 목록뿐**이다. 전체 18쪽 중 정답이 있는 쪽은 2쪽이고, 나머지 쪽의 정확도는 모른다(경고 개수는 정확도가 아니다).
2. **목록 지시문("문장·기능 항목도 1건씩")은 3쪽에서 상단 문장이 빠지는 것을 본 뒤 고쳤고 같은 쪽에서 재시험했다** → 3쪽 26/26은 낙관적이다.
3. **읽기가 어긋나는 것은 비결정적이다.** 같은 쪽을 여러 번 돌리면 어떤 실행에서는 열 누락이 나오고 어떤 실행에서는 안 나온다(11쪽 3회 실행 결과가 다름). 다수결도 다수가 같은 실수를 하면 못 잡는다(체계적 오류) — 경고로 사람이 보게 하는 것이 최선이다.
4. 표 구조 검사의 '크기가 커졌는데 값이 줄어듦'(review)은 **원본에서 정상인 감소도 경고한다**(예: 장착 플랜지 h2 22→18은 원본 표의 값). 노이즈가 있다.
5. 서술·목록 쪽의 '누락 확인' 경고가 많다(2쪽 8개, 14쪽 7개, 16쪽 4개). **사양과 관련 있는 문장인지 AI가 판단한 것**이라 정확도를 검증하지 않았다.
6. 시간·비용: 18쪽 전체 약 4분(병렬 3, CLI). 정확한 사용량은 기록하지 않았다. 문서 내용이 Anthropic으로 전송된다.
7. **API(이미지 입력) 경로는 스텁 테스트만 했고 실제 호출은 검증하지 못했다.** 서버(Railway) 배포에서는 CLI를 쓸 수 없어 이 경로가 필요하다.
8. 화면(UI)은 아직 없다. 이 결과는 API로만 얻을 수 있고 후보·판정에는 연결되지 않았다(4-2·4-3).
