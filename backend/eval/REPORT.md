## 알려진 한계

- **표본이 작다.** 5건·37항목. 신뢰구간이 넓고(CLI 82–99%), 문서 종류가 형식승인서뿐이라 **데이터시트 추출은 평가하지 못했다.**
- **온도(`temp_max`)는 정의가 모호하다.** 좌석 재질별 상한 중 최저값을 정답으로 정의했다(보수적). 규칙 추출기는 이를 못 따라 `Victaulic`에서 120 vs 정답 82로 "오답"이 났는데, 문서 머리말 값(0~120°C)이라 정의상의 불일치에 가깝다.
- **ABO의 플랜지에서 `ANSI class 300 /150` 뒤 150을 규칙이 놓침**(조용한 오류). 미수정.
- **경고가 과하다:** CLI 결과에서 규칙과 불일치·단독 추출로 표시된 값 16건(규칙 수정 후 7건)이 **전부 실제로는 정답**이었다. 오류 검출 실적은 이 표본에서 0건(오류 자체가 없었음).
- **재질 라벨의 한계:** ABO 재질(1.0625/1.4408)은 앱 재질 코드와 대응이 모호해 채점에서 제외했다.
- **LLM 결과는 매번 다를 수 있다.** 1회 실행 결과다(반복 측정 안 함).
- **비용:** 평가 CLI 호출 6회(스크립트 오류로 1회 재실행 포함). 정확한 사용량은 기록하지 않았다.

# 사용 제한 조건 해석 평가 (소규모 시험, n=5 문서 · 라벨 35건)

- 실행: `cd backend && .venv/bin/python -m eval.run_eval_restrictions [rules|cli] [--refresh]` · 정답: `eval/labels_restrictions.json`(추출 전에 작성, 작성자 Claude, **사람 검수 전**)
- 승인서의 제한 문장(“해수 계통 사용 불가”, “여객선 빌지 사용 불가” 등)을 읽고 **금지/조건부/주의 · 해당 사용 상황 · 재질 범위 · 적용 조건**으로 구조화한다. 라벨은 사용 상황 어휘(해수·청수·밸러스트·빌지·연료유·화물유·LNG/LPG·내화·선측·충돌격벽·공기·인화성 유체) 안의 제한만 35건.
- 판정 엔진은 확정된 제한만 선박의 사용 계통에 **규칙으로** 대조한다. ‘제외’는 **제품 전체 금지(또는 제품의 모든 재질이 금지 대상)** 일 때만, 조건부·특정 구성 한정·일부 재질 한정 금지는 ‘주의’.

| 방식 | 재현율(엄격) [95% 신뢰구간] | 재현율(판정 효과)† | 근거 없는 ‘제외’‡ |
|---|---|---|---|
| 규칙 기반 — **수정 전** | 27/35 = 77% [61–88%] | 27/35 = 77% | **6건** |
| 규칙 기반 — 수정 후* | 31/35 = 89% [74–95%] | 30/35 = 86% [71–94%] | 1건 |
| **Claude CLI** (claude-sonnet-5) | 31/35 = 89% [74–95%] | 33/35 = 94% [81–98%] | **0건** |

† 판정 효과 기준은 **결과를 본 뒤에 추가한 지표**다. Claude 는 위치·선종 조건이 붙은 금지 4건을 ‘금지+적용 조건’ 대신 ‘조건부+적용 조건’으로 분류했는데, 엔진에서는 둘 다 ‘주의’라 판정이 같다. 그래서 엄격 기준(kind 까지 일치)과 효과 기준(엔진 효과 등급 일치)을 함께 적는다.
‡ 제품 전체·재질 범위 금지로 잘못 추출돼 **판정에서 부당하게 제외될 수 있는** 항목. 규칙 기반 수정 전의 6건은 전부 조건을 무시하고 전면 금지로 읽은 것(예: ‘여객선의 빌지 계통 사용 불가’ → 빌지 전체 금지, ‘이중저 터널 내 배관’ → 위치 조건 무시).
\* 규칙 기반 수정은 **같은 5건에서 발견한 결함을 고친 것이라 낙관적**이다(독립 평가 아님). 수정 내용: 목록 항목·번호 항목의 문장 경계, ‘low fire risk’를 내화 계통으로 오인하던 것, 조건(위치·선종·형식·수치) 표현이 있으면 적용 조건으로 표시.

## 해석
- **가장 위험한 오류는 놓침이 아니라 ‘조건을 무시한 전면 금지’**였다. 규칙 기반은 수정 전 6건(부당 제외 가능)이었고, Claude 는 조건을 적용 조건으로 붙여 **부당 제외 0건**이었다.
- 규칙 기반도 문서군에 맞춰 손보면 이 5건에서는 Claude 와 비슷한 수준까지 올라간다. **Claude 는 손보지 않고 그 수준**이었지만, 처음 보는 문서군에서 어느 쪽이 더 잘 일반화되는지는 **이 시험으로 알 수 없다**.

## 한계 (반드시 함께 말할 것)
1. **표본이 작다**: 문서 5건, 라벨 35건. 신뢰구간이 넓다.
2. **라벨은 Claude 가 작성했고 사람 검수 전**이다. 같은 계열 모델의 공통 맹점이 있을 수 있다. 라벨 밖(사용 상황 어휘 밖)의 제한은 평가하지 않았다.
3. **Claude 프롬프트의 ‘조건부·위치·선종 한정 금지를 전면 금지로 만들지 말 것’ 규칙은 이 문서들의 내용을 본 뒤에 썼다**(문서 내용에 대한 사전 지식이 프롬프트에 반영됨). 완전히 독립적인 결과가 아니다.
4. **W3 라벨 문제**: Witzel ‘회주철 밸브는 가연유 탱크에 설치 불가’ 항목은 재질 범위 금지로 추출된 것이 사실 맞는 해석인데, 라벨을 수치 조건 항목과 합쳐 ‘조건 필요’로 적었다. 규칙 기반의 남은 ‘부당 제외 1건’은 이 **라벨링 문제**다.
5. **계통 → 사용 상황 매핑은 개발팀의 가정**이다(예: 밸러스트는 해수 포함, 소화는 내화 요구 계통). 현업 검증 전이며 화면에 그대로 표시한다.
6. Claude 는 **1회 실행 결과**다(비결정적). 사용 제한 해석은 **담당자가 원문과 대조해 확정한 것만** 판정에 반영된다.
7. 비용: 이 평가에서 CLI 호출 5회(약 7분 30초). 정확한 사용량은 기록하지 않았다.
