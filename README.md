# MARINE MATCH

선박 요구조건 기반 **대체 기자재 검토** 서비스 — 납품 지연·단종 시, 등록된 제품에서 후보를 찾고
사양 충족 여부를 **문서 원문·페이지 근거**와 함께 보여줍니다. (K-조선 해커톤 2026)

## 실행

```bash
# 1) 백엔드 (FastAPI + SQLite)
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cd .. && npm run api            # http://127.0.0.1:8000

# 2) 프론트엔드 (Vite + React)
npm install && npm run dev      # http://localhost:5173  (/api 는 8000 으로 프록시)
```

### 추출 방식 (자동 우선순위)

1. **Claude API** — 백엔드를 띄우는 셸에 `ANTHROPIC_API_KEY` 설정 (모델: `MARINE_LLM_MODEL`)
2. **Claude CLI** — API 키 없이 `claude` CLI(로그인된 계정)로 `claude -p` 호출. `MARINE_CLI_MODEL`, `MARINE_CLI_TIMEOUT` 로 조정
3. **규칙 기반** — 위 둘이 없거나 실패하면 자동 폴백

LLM 결과는 원문 인용이 실제 페이지에 있는지 검증하고, 규칙 추출과 값이 다르거나 LLM만 뽑은 항목은
**⚠ 검증 필요**로 표시해 기본 선택에서 제외합니다. (CLI 호출은 계정 사용량을 소모하며 문서 내용이 Anthropic으로 전송됩니다.)

## 구조

| 위치 | 역할 |
|---|---|
| `backend/app/engine.py` | 요구조건 대조 엔진 — 수치·단위·필수조건·**인증 유효기간**은 AI가 아닌 규칙으로 판정, 자료가 없으면 UNKNOWN |
| `backend/app/extract_rules.py` | 규칙 기반 PDF 추출(사양·인증·유효기간·원문 줄·페이지) |
| `backend/app/extract_llm.py` | Claude API 구조화 출력 추출 + **원문 인용 검증**(환각 차단) |
| `backend/app/extract_cli.py` | Claude CLI(`claude -p --json-schema`) 추출 — API 키 불필요 |
| `backend/app/extract.py` | API → CLI → 규칙 순 선택·폴백, 규칙 추출과 교차검증 |
| `backend/app/db.py` | SQLite 저장소 + 감사 로그(누가·언제·무엇을 확정했는가) |
| `src/` | 선박 선택·등록 → 검색조건 → 후보 → 비교·근거(PDF 원문) → 검토 보고서 → 업로드·확인 |

## 선박(프로젝트) 관리

- 선박마다 선급·사용 계통·필요 납기일과 **자기 요구조건**이 저장된다(수정은 자동 저장). 선박을 바꾸면 그 조건으로 후보가 다시 판정된다.
- 새 선박은 기존 선박의 조건을 복제하며 **선급과 필요 납기만** 자동 조정된다. 재질·구경 등은 ②에서 수정한다.
- 시연용 가상 선박 2척(A호 DNV, B호 KR)이 기본 제공된다. **모든 선박을 삭제할 수 있고**(마지막 1척은 보호), 우측 상단 초기화로 복구된다.
- **인정 선급을 여러 개 지정**할 수 있다(예: DNV 또는 KR). 요구조건의 선급 값이 `DNV|KR` 목록이 되고, **인정 선급 중 하나라도 유효한 형식승인이 있으면 충족**한다(전부 만료면 미충족). 어떤 선급 승인을 인정할지는 선급 규정·선주 요구에 따라 다르므로 사용자가 정한다.
- **교체 대상 기자재**(부품 종류·기존 모델·교체 사유)는 선박마다 바꿀 수 있다. 부품 종류는 같은 요구조건 항목을 쓰는 밸브 계열(버터플라이·게이트·글로브·체크)만 지원하며, 후보는 선택한 부품 종류로 등록된 제품만 나온다. 부품 종류를 바꿔도 요구조건은 유지되므로 ②에서 확인해야 한다.
- 기자재 DB(제품·문서)는 모든 선박이 공유한다. 제품 삭제 시 확정 자료와 그 제품만 쓰던 업로드 문서도 함께 삭제되고, 확정한 사양·인증은 개별 삭제(→ ‘확인 필요’로 복귀)할 수 있다.
- 업로드한 문서의 제품 종류가 등록 제품의 부품 종류와 다르면(예: 체크 밸브 승인서를 버터플라이 제품에 업로드) 경고한다.

## 사용 제한 조건 해석 (AI가 정형화를 넘어 ‘해석’하는 부분)

승인서에는 값이 아니라 **문장으로 쓰인 제한**이 있다(“Seawater applications는 사용 불가”, “스테인리스는 해수 접촉 금지”, “여객선 빌지 사용 불가”).
1. **AI 해석**: 제한 문장을 읽고 `금지/조건부/주의 · 해당 사용 상황 · 재질 범위 · 적용 조건(시트·위치·선종·수치 등)`으로 구조화하고 원문 인용을 붙인다(Claude CLI/API, 규칙 기반은 폴백). 인용이 실제 페이지에 없으면 버린다.
2. **담당자 확정**: 화면에서 원문과 대조해 확정한 것만 사용한다(수준 수정·개별 삭제 가능). 규칙 기반 해석은 오해석 가능성이 높아 기본 선택하지 않는다.
3. **규칙 대조**: 확정된 제한을 선박의 **사용 계통**(예: 해수 냉각 → 해수)과 제품 재질에 규칙으로 대조한다. AI가 판정마다 다시 판단하지 않는다.
4. **보수적 차단**: ‘제외’는 제품 전체에 대한 명확한 금지일 때만. 조건부·특정 구성 한정·일부 재질 한정은 ‘주의’로 표시한다. 문서에 제한이 없다고 해서 제한이 없다는 뜻은 아니므로 ‘문서 미분석’은 판정에 영향을 주지 않는다.

계통 → 사용 상황 매핑(`backend/app/contexts.py`)은 개발팀의 가정이며 현업 검증이 필요하다. 평가 결과와 한계는 [backend/eval/REPORT.md](backend/eval/REPORT.md).

## 흐름의 핵심 원칙

1. 문서에서 **추출**(규칙 또는 Claude) → 2. **담당자가 원문과 대조해 확정** → 3. 확정된 값만 **판정**에 반영.
추출 값은 확정 전까지 판정에 쓰이지 않습니다. 판정마다 문서·페이지·추출 방식·확인자가 남습니다.

## 추출 정확도 평가

실제 형식승인서 5건으로 측정한 소규모 시험 결과는 [backend/eval/REPORT.md](backend/eval/REPORT.md) 에 있다
(Claude CLI: 재현율 95% [82–99%], 오답 0건 / 규칙 기반: 41% → 수정 후 84%). **n=5 로 통계적 수치가 아니며**,
라벨은 Claude 가 작성했고 사람 검수 전이다.
