# Railway 배포 안내

한 개의 서비스가 **빌드된 프론트엔드 + FastAPI**를 함께 제공한다(`Dockerfile`). DB(SQLite)와 업로드 파일은 **Volume**에 저장한다.

## 1. 반드시 알아둘 것

- **이 앱에는 사용자 계정이 없다.** 공개 URL 을 만들면 누구나 문서 업로드·삭제·초기화가 가능하고 실제 승인서 PDF 도 내려받을 수 있다.
  → 운영 모드에서는 `APP_PASSWORD` 가 없으면 **서버가 기동을 거부**한다(HTTP Basic 인증, 사용자명 기본값 `team`).
- **Claude CLI 추출은 서버에서 동작하지 않는다**(서버에는 로그인된 `claude` 가 없다). 서버에서는 **Claude API 키** 또는 **규칙 기반 추출**만 가능하다.
- **Claude API 경로는 아직 실제 호출로 검증하지 못했다**(스텁 테스트까지). 첫 배포는 API 키 없이 띄워 화면·저장·업로드를 확인한 뒤, 키를 넣고 문서 1건으로 시험할 것.
- API 키를 넣으면 **문서 내용이 Anthropic 으로 전송되고 사용량 요금이 발생**한다. 암호를 아는 사람은 누구나 추출을 실행할 수 있다.
- **인스턴스는 1개로 유지**한다(SQLite 단일 파일). 스케일 아웃하면 데이터가 갈라진다.
- Railway 의 요금·무료 범위는 이 문서에 적지 않았다(바뀔 수 있음). 계정의 요금제를 직접 확인할 것.

## 2. 배포 순서 (Railway 웹)

1. [railway.com](https://railway.com) 에서 로그인 → **New Project → Deploy from GitHub repo**
2. GitHub 연동에서 이 저장소를 선택(비공개 저장소면 Railway GitHub 앱에 접근 권한을 줘야 함)
3. 빌드는 저장소 루트의 `Dockerfile` 과 `railway.json` 을 자동으로 사용한다.
4. 서비스 → **Variables** 에 아래 값을 추가
5. 서비스 → **Volumes → New Volume**, Mount Path 를 **`/data`** 로 지정
6. **Settings → Networking → Generate Domain** 으로 공개 주소 생성
7. 배포가 끝나면 주소에 접속해 사용자명 `team` 과 설정한 암호로 로그인

## 3. 환경변수

| 이름 | 필수 | 설명 |
|---|---|---|
| `APP_PASSWORD` | **필수** | 접속 암호. 길고 예측하기 어려운 값을 쓸 것 |
| `APP_USER` | 선택 | 접속 사용자명(기본 `team`) |
| `MARINE_DATA_DIR` | 선택 | 기본 `/data`(Dockerfile 에 설정됨). Volume 마운트 경로와 같아야 함 |
| `ANTHROPIC_API_KEY` | 선택 | 있으면 Claude API 추출을 사용. 없으면 규칙 기반 추출 |
| `MARINE_LLM_MODEL` | 선택 | API 모델 변경(기본 `claude-opus-5`) |
| `MARINE_ALLOW_OPEN` | 비권장 | `1` 이면 암호 없이 기동 허용(공개 접근을 의도할 때만) |

`PORT` 는 Railway 가 자동으로 넣는다.

## 4. 배포 후 점검

1. 주소로 접속 → 브라우저의 로그인 창에 `team` / 암호 입력 → 화면이 열리는가
2. 선박 2척·후보 15개가 보이는가(첫 기동 때 시드가 들어간다)
3. 제품 등록 또는 문서 업로드 → **샘플 문서**로 추출·확정 → 판정이 바뀌는가
4. **재배포(Redeploy) 후에도 확정한 데이터가 남아 있는가**(Volume 이 제대로 붙었는지)
5. (API 키를 넣었다면) 추출 방식에서 Claude API 로 문서 1건 시험

## 5. 알려진 한계

- 사용자별 로그인이 없다(공용 암호 하나). 누가 확정했는지는 화면에 입력한 이름으로만 기록된다.
- 화면의 **초기화** 버튼은 암호를 아는 누구나 눌러 데이터를 지울 수 있다.
- **Dockerfile 은 로컬에서 실제 빌드해 보지 못했다**(개발 PC 에 Docker 없음). 대신 같은 단계(프론트 `npm ci && npm run build`, 백엔드 `requirements-prod.txt` 설치·기동, 정적 파일 경로)를 깨끗한 폴더에서 재현해 검증했다. 첫 빌드에서 오류가 나면 로그를 확인할 것.
- Python 은 이미지에서 3.12 를 쓴다(개발은 3.14). 테스트는 3.14 에서만 실행했다.
- 업로드 파일은 Volume 에 쌓이며 자동 정리되지 않는다.
